# 1. Introduction

Multi-agent Large Language Model (LLM) architectures have emerged as the dominant paradigm for solving complex, multi-step reasoning and software engineering tasks. Frameworks such as LangGraph, AutoGen, and CrewAI enable developers to decompose monolithic prompts into specialized communicating agents. However, running autonomous agent teams introduces severe operational failure modes:
1. **Unbounded Financial & Token Expenditure:** Cascading agent dialogues, repetitive tool calls, and infinite loops frequently exhaust external API credit allocations before completing the primary objective.
2. **Silent Quality Degradation & Error Propagation:** Early hallucinations or fabricated citations generated by an upstream research agent propagate unchecked through downstream synthesis agents, silently corrupting final outputs.
3. **Static Team Rigidity:** Existing runtimes assign fixed agent roles, model checkpoints, and prompt templates before execution. If an agent consistently underperforms or hallucinates in-flight, the entire team fails or requires complete restart.

Despite the proliferation of multi-agent frameworks, current approaches treat governance as an internal concern of the user application or an afterthought left to external proxy rate-limiters.

We present **OASIS (Optimized Agent Supervision & In-flight Substitution)**, an external, non-intrusive supervisory layer for multi-agent LLM systems. Positioned between user-defined agent runtimes and external LLM provider APIs, OASIS intercepts API calls to deliver three unified supervisory mechanisms:
- **Pre-execution Task Complexity Estimation (TCE):** Predicts minimum viable team size ($k=1\dots5$) and retrieves verified team topologies from Configuration Memory (CM), preventing over-allocation.
- **Strict 4D Real-Time Budget Enforcement (RBE):** Meters and enforces admission control across four concurrent dimensions (Tokens, Cost USD, Wall Time, and Call Count) with zero unobservable proxy dimensions like GPU/RAM.
- **Real-Time Performance Monitoring (RTPM) & In-Flight Substitution:** Cascades through a three-layer evaluation hierarchy (L1 Embedding Cosine, L2 LLM-Judge Rubric, and L3 Deterministic Verifiers) to detect underperformance, triggering dynamic agent substitution from an Agent Template Library (ATL) with state preservation.

Crucially, OASIS guarantees **offline replay purity**: every model interaction is hashed and recorded to append-only JSONL sinks, allowing reviewers to reproduce all empirical findings with zero network calls and zero API expenditure.
